# EconoCausal: Design

## Goal

Estimate how much a discount changes a customer's probability of buying again, for each customer (ITE). Use these estimates to decide who should get a $10 or $20 discount under a fixed budget.

Source: Project 2 doc (Dynamic Pricing via Double Machine Learning).

## Data

- **Mock retail dataset** (required by the doc). Generated by `scripts/generate_mock_data.py`.
- Feature distributions (prices, income proxy, prior orders, spend, season) are taken from the Olist dataset in `data/raw/`, so the mock data looks like real retail data.
- Discount effects and outcomes are planted by us, so the true answer is known.
- Olist is used only as the source of realistic distributions and as a secondary check. It has no true effect, so it cannot validate the method on its own.

## Unit of analysis

- One row per customer.
- Pre-treatment features are measured before the first discount offer.

## Treatment

- Discount level in reais: $0, $10, $20.
- Compared against no discount ($0).
- Matches the doc's use case of comparing $10 vs $20.

## Outcome

- Repeat purchase within 180 days of the offer (0 or 1).
- Measured after treatment, for every customer.

## Confounders (measured before the offer)

- Income proxy (state-based, or simulated from Olist's distribution).
- Prior orders.
- Days since previous order.
- Prior spend.
- Season.

Not allowed as confounders: reviews, payments after the order, or any variable measured after the offer.

## Causal graph (DoWhy)

Each confounder points to both the discount and the outcome. The discount points to the outcome.

Refutation tests come at Mid-Review and are labelled as stress tests, not proof.

## Estimation

- Double ML with LightGBM base learners.
- Cross-fitting with folds grouped by customer, so one person's rows never sit in both training and test folds.
- LinearDML for the average effect.
- A forest or LightGBM DML for per-customer ITEs.

## Validation (must pass before reporting results)

- ATE: naive gap vs DML vs planted ATE. DML should be closer to the planted value than the naive gap.
- ITE: correlation between estimated and planted ITE, and whether the ranking separates high and low responders.
- Overlap: discount propensity should stay away from 0 and 1.

## Outputs

- `data/mock/mock_customers.csv`: the simulated dataset, including the true ITE for checking only (never a model input).
- `data/processed/ite_scores.csv`: one row per customer with `customer_id`, `ite_10`, `ite_20`, and the features used. Read by the optimizer and the dashboard.
